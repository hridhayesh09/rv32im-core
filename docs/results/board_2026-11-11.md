# Board run, 2026-11-11: CoreMark and the SDRAM burst fix

DE10-Lite, 50 MHz. Core with the default branch predictor (32-entry BTB, gshare with 256 counters,
4-entry return stack). CoreMark 1.0 from EEMBC (third_party/coremark), 2K performance run, port in
`sw/coremark`, GCC 13.2.0 `-O2 -ffreestanding -march=rv32im_zicsr_zifencei -mabi=ilp32`. Time is the
cycle counter; CoreMark picked 2000 iterations (over 10 s, so the runs are valid).

## CoreMark

| Build and placement | Iterations | Timed cycles | Time | CoreMark/MHz | CoreMark at 50 MHz | CPI | Mispredicted branches |
|---|---|---|---|---|---|---|---|
| Full SoC (NPU, no caches), program in on-chip RAM | 2000 | 741,126,904 | 14.82 s | **2.699** | 134.9 | 1.177 | 12.8 % |
| CPU-only (4 KB I$ + D$), program in on-chip RAM | 2000 | 741,126,904 | 14.82 s | **2.699** | 134.9 | 1.177 | 12.8 % |
| CPU-only (4 KB I$ + D$), program in SDRAM through the caches | 2000 | 751,703,684 | 15.03 s | **2.661** | 133.0 | 1.194 | 12.8 % |

CoreMark/MHz = iterations x 10^6 / cycles. CoreMark's own "Iterations/Sec" line divides by whole
seconds, so it rounds (142 and 133 instead of 134.9 and 133.0).

The two RAM runs took exactly the same number of cycles: the NPU and the caches don't touch a
program in on-chip RAM. From SDRAM, the 4 KB caches cost 1.4 % (10,576,780 cycles).

## SDRAM burst reads: found and fixed on the board

The first run of the cached build failed: the bootloader's LOAD of CoreMark into SDRAM was
rejected (`ERR crc`), and `sdram_test.bin` failed address lines, random words, bytes and copy
(simulation passed). The cached build moves 16-byte lines; the board had only ever run the
single-word path before.

1. The fitter report showed `DRAM_DQ[*]` with no input register in the I/O cell and a
   combinational fan-out of 8: each pin went straight into the 8-slot burst buffer, so the
   capture time depended on routing.
2. With a rising-edge I/O input register (`FAST_INPUT_REGISTER`) at 60 ns after READ:
   still failing, now everywhere.
3. A new diagnostic (`sw/soc/sdram_diag.c`, using a new uncached SDRAM window at 0x5000_0000)
   split the paths. Single words read back as their upper halfword twice (`9f379f37` for
   `9f3778b0`), and line reads returned correct halfwords shifted by one: writes were fine, reads
   were captured one cycle late.
4. Fix: the I/O input register clocked on the falling edge, 50 ns after READ, the middle of the
   window measured with edge-ml-accelerator/boardtest (clean from 50 to 70 ns). After that:

```

1 words: uncached write, uncached read: 0 errors
2 burst reads: uncached write, cached read: 0 errors
3 burst writes: cached write, uncached read: 0 errors
4 both: cached write, evict, cached read: 0 errors
DIAG PASS
```
```

random words: ok

SDRAM PASS
```
